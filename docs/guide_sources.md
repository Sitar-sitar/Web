# 推奨ステータス定義の設計メモ

本ツールの基礎優先度は、役割別に会心アタッカーでは会心率・会心ダメージ、持続ダメージアタッカーでは速度・攻撃力%、撃破キャラクターでは撃破特効・速度、調和サポーターでは速度・耐久、デバフサポーターでは速度・効果命中、ヒーラーでは効果抵抗・速度を重視する方針で設計した。

この方針は、ゲームエイトの「遺物厳選はいつからやるべき？・おすすめ効果」（2026年8月18日に確認）にある役割別の遺物ステータス選定を基礎とする。個別キャラクターの推奨値は、実装時点の用途を想定した初期値であり、編成・光円錐・凸状況に応じて今後更新する余地を残している。

参照: https://game8.jp/houkaistarrail/526191

## 公開UIDフォールバックの確認メモ

2026年8月18日に、`https://enka.network/api/hsr/uid/{UID}` が公開中の崩壊：スターレイルUIDに対してJSONを返すことを確認した。レスポンスはゲームに近い生データ形式で、`detailInfo.avatarDetailList` にキャラクター、光円錐、遺物、各遺物の `_flat.props` が含まれる。表示用の名称・属性・画像は別途ゲーム静的データとの結合が必要である。

同日、対象UID `806071233` をアプリのローカル照会経路で検証し、MiHoMoの代わりにEnkaフォールバックから8名の公開キャラクター、6部位の遺物、遺物のメイン・サブステータスを取得できることを確認した。

Enka生データの名称補完には、StarRailResの最新の日本語インデックス（`characters`、`light_cones`、`relic_sets`）を用いる。これはIDから名称・属性・運命・遺物セットを解決する静的データであり、フォールバック側では24時間キャッシュする。[StarRailRes](https://github.com/Mar-7th/StarRailRes)

同日、対象UIDの実画面を再検証し、最新の静的データ結合によりキャラクター名、属性・運命、光円錐名、遺物セット名が表示され、遺物由来の推定会心率・会心ダメージ・速度・攻撃力%に対する3水準の達成判定が動作することを確認した。推定値にはキャラクター固有値および戦闘中バフを含めない。

StarRailResの`character_promotions`は昇格段階ごとの基礎HP・攻撃力・防御力・速度・会心率・会心ダメージを、`light_cone_promotions`は光円錐の基礎ステータスを、`character_skill_trees`は各軌跡ノードのステータス加算値を保持する。Enkaの`promotion`・`level`・`skillTreeList`と結合すれば、遺物以外の基礎値と解放済み軌跡を比較値へ反映できる。[StarRailRes](https://github.com/Mar-7th/StarRailRes)

最終検証では、ローカルの`build.lookup`経路で対象UIDを照会し、MiHoMoが利用できない状態からEnkaへ切り替わること、8名の公開キャラクターについて日本語名・属性・運命・光円錐名・遺物セット名を解決できることを確認した。選択中の遠坂凛では会心率70.8%、会心ダメージ129.7%、速度140.2、攻撃力%61.4%が基礎値・解放済み軌跡・遺物に基づく比較値として返され、達成判定にも反映された。戦闘中の一時バフや光円錐の条件付き効果は含めない。

未解決IDについてもUI検証を行った。光円錐および遺物セットの静的データを意図的に未解決とした照会レスポンスで、画面に`未解決（ID: 99999）`が光円錐欄と装備遺物欄の両方で表示されることを確認した。
